### MODELING INSTRUCTIONS ###
Follow the Manager TIP while remaining faithful to the document and maintaining logical consistency and reuse of existing ontology elements.

(1) COMMON MISTAKES IN REIFICATION
* Use reification only when needed; do not create pivot classes when a direct relation is sufficient.
* When reification is used, connect the pivot to related entities through object properties, not `rdfs:subClassOf`.
(2) COMMON MISTAKES IN CLASS EXTRACTION
* Do not treat individuals or literal values such as dates, strings, or numbers as classes.
* Do not create unnecessary or redundant classes.
(3) COMMON MISTAKES IN HIERARCHY EXTRACTION
* Use `rdfs:subClassOf` only for genuine taxonomic relations.
* Do not invent unsupported hierarchy levels or classes.
(4) COMMON MISTAKES IN OBJECT PROPERTIES
* Ensure object properties connect appropriate ontology entities with consistent domain and range.
* Do not replace ordinary relations with unnecessary reification.
(5) COMMON MISTAKES IN DATA PROPERTIES
* Use data properties only for literal values and create only properties that are actually needed.
(6) COMMON MISTAKES IN WORKFLOW
* Return only complete, valid Turtle content with all required prefixes, classes, properties, and assertions.
(7) COMMON MISTAKES IN ONTOLOGY DESIGN
* Instantiate relevant facts; do not define only classes and properties.
* Avoid unused, redundant, or logically inconsistent ontology elements.

1. Instantiate named entities and factual relationships explicitly present or clearly supported by the document.
