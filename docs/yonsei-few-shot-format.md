# Yonsei Few-shot 생성 형식

비교 기준은 현재 [NeOn 설정](../app/neon-prompts.json)과 사용자가 첨부한 원문을 보존한 [prompt-set.md](../examples/neon/prompt-set.md)의 활성 예시입니다. 보관용 전체 온톨로지 조각이나 GitHub의 제외된 커밋을 복구한 것이 아닙니다. 모든 NeOn-GPT 구현·논문의 공통 규칙이라고 해석하지 않습니다.

## 단계별 적용

| 단계 | 현재 NeOn의 Few-shot 입력 | Yonsei 생성 지시 |
| --- | --- | --- |
| 01 명세 | 별도 입력 없음 | Yonsei 확장: 짧은 예시 원문 → 목적·범위·사용자·사용 용도·기능/비기능 요구사항, 2건 |
| 02 재사용 | `few_shot_reuse`: 제목 + 작은 관계 조각 6건 | 같은 참조 조각 6건. 예시 요구사항·관계 triple·재사용 적합성/불확실성 메모. 완성 온톨로지나 전체 명세 생성이 아님 |
| 03 CQ | `few_shot_cqs`: 스타일·범위가 다른 질문 6개 | 가상 원본 문서 + CQ1–CQ6이 들어 있는 JSON 1개. 문단 ID 없이 정확한 근거 인용을 반환하고 두 문단에 걸친 질문은 인용 2개로 표현 |
| 04 추출 | `few_shot_entity_extraction`: Q·후보 개념/관계·모델링 메모 6건 | 해당 설명 구조 + 건별 `elements/triples` JSON. 클래스·프로퍼티·triple의 CQ 연결과 여러 CQ에 연결되는 요소 포함 |
| 05 개념 모델 | 별도 입력 없음 | Yonsei 확장: 작은 추출 JSON → 전체 개념 모델 JSON 1건. 입력 요소·IRI·CQ 연결 보존, subclass와 일반 관계 구분 |
| 06 확장 I | `few_shot_reuse` 재사용 | 참조 조각 + 현재 모델·CQ 질문 → 추가분 JSON, 6건 중 1건은 추가할 것이 없는 no-op |
| 07 확장 II | 같은 `few_shot_reuse` 재사용 | 1차 추가분까지 포함한 모델에서 남은 부분만 추가, 6건 중 1건은 이미 반영된 관계의 중복을 막는 no-op |
| 08 직렬화 | 별도 입력 없음 | Yonsei 확장: 작은 전체 모델 JSON → 완전한 Turtle 1건. 모든 클래스/프로퍼티·triple·CQ 주석 보존 |
| 09 Refine | Yonsei 고유 단계 | 보관한 문단·CQ·요소 연결을 사용. Few-shot 생성 없음 |

NeOn의 6개 참조 예시가 모든 단계에서 무조건 6개의 완성 산출물을 뜻하지는 않습니다. 01·05·08에는 원래 별도 Few-shot 필드가 없으므로 기존 Yonsei 기능을 유지한 보조 예시로 명시했습니다. NeOn의 뒤쪽 데이터 프로퍼티·개체 추가 단계용 예시를 08 직렬화 예시로 가져오지 않습니다.

## 생성과 실행의 경계

- 생성 지시문 8개와 공통 생성 System 지시문은 [yonsei-prompts.json](../app/yonsei-prompts.json)에 있습니다. 단계별 출처·개수는 `provenance.few_shot_reference`에 기록했습니다.
- 생성 결과는 `few_shot_01`–`few_shot_08`로 현재 단계 실행에 연결됩니다. 단계 실행 템플릿과 전송 문맥은 아래 원문 전달 정책에 맞추었습니다. CQ 수·페르소나·단계 순서와 자동/수동 실행 방식은 유지합니다.
- 예시 문단과 CQ ID는 예시 내부에서만 유효합니다. 실제 문서 근거, 승인된 CQ, 실제 실행 결과로 승격하지 않습니다. 비디오게임 예시의 클래스 목록도 강제하지 않습니다.
- JSON 예시의 제목·설명은 JSON 밖에 두고, 문자열과 Turtle 리터럴의 이스케이프를 보존하도록 지시합니다. 전체 생성 응답에는 한 쌍의 출력 마커만 사용합니다.
- 생성 프롬프트에는 도메인명·키워드·페르소나·재사용 지침·CQ 목표 수와 단계 양식·사용자 생성 지시문만 넣습니다. 실제 원문·문단·CQ 근거·이전 산출물·온톨로지·기존 Few-shot은 자동 전달하지 않습니다. 이 입력들의 변수는 생략 표시로 치환하며 알 수 없는 사용자 변수는 값을 주입하지 않습니다. 확인 팝업과 실행은 같은 조립 함수를 사용합니다.
- 01·03단계의 예시 원문은 가상으로 생성하고, 04–08단계 예시는 실제 단계와 같이 CQ ID·질문과 모델을 사용하도록 지시합니다. 예시 입력에 문단 근거를 요구하지 않습니다.
- 기존 로그를 불러오면 저장된 생성 프롬프트·결과를 보존하며 새 기본값으로 강제 덮어쓰지 않습니다. 기본 지시문 변경은 새 세션에 적용되지만, 실제 입력을 자동으로 제외하는 조립 로직은 기존 세션에도 적용됩니다. 단, 사용자가 지시문·양식·기타 허용 입력에 원문을 직접 붙인 경우에는 그대로 전송합니다.
- 모의 생성은 기존 고정 구조 예시입니다. 변경한 지시문을 해석하거나 단계별 개수만큼 LLM 예시를 생성하지 않습니다. 새 형식에 따른 실제 생성은 API 모드에서 확인해야 합니다.

## 본 실행의 원문 전달 경로

| 단계 | 모델에 자동 제공하는 문맥 | 원문·문단 근거 |
| --- | --- | --- |
| 01 명세 | 도메인 설정, 전체 문서 | 제공 |
| 02 재사용 | 01 명세, 재사용 지침 | 별도 제공 안 함 |
| 03 CQ | 01·02 요구사항, 원본 문서 텍스트 | 원문을 그대로 한 번 제공. 문단 JSON·ID 목록은 보내지 않고 출력의 `evidence.text`를 세션·로그에 보관 |
| 04–07 모델 생성·확장 | CQ `id`·`question`, 단계별 이전 모델·재사용 지침 | 제공 안 함. 요소·triple에는 `cq_ids`만 유지 |
| 08 Turtle | 누적 모델, CQ `id`·`question`, 요소 목록 | 제공 안 함. 요소의 CQ 주석을 보존 |
| 09 Refine | 문단 → 저장된 CQ → `cq_ids`로 연결한 누적 요소, 전체 TTL | 제공 |

03단계 저장본을 변경하지 않고 전송용 사본만 만듭니다. 특히 04단계에서는 CQ 변수뿐 아니라 ‘이전 단계 출력’ 래퍼에서도 근거를 제외합니다. 잘못된 CQ JSON은 그대로 전달하는 대신 빈 목록과 수정 안내를 사용하며, 저장본과 검증 경고는 유지합니다. 09단계는 보관한 근거를 다시 사용합니다. 문단 연결은 인용문이 정확히 포함된 문단으로만 만들며 문자열 유사도로 추측하지 않습니다. 줄바꿈 형식(CRLF/LF)만 비교 시 통일하고 공백·문구는 임의 보정하지 않습니다. 여러 문단에 반복되는 인용은 더 긴 인용을 요구하고, 문단 경계를 가로지르는 인용은 문단별로 나누도록 요구합니다. 과거 로그의 명시적인 문단 ID는 올바른 경우 그대로 지원하며 잘못된 ID를 자동 교정하지 않습니다.

원문 입력의 비교 기준은 첨부판 NeOn [Step 03](../examples/neon/prompt-set.md)의 `{document}`입니다. 이 판본은 이전 명세·전체 문서·Few-shot을 함께 제공합니다. [저자 공개 extended 코드](https://github.com/NadeenAhmad/neon-gpt-extended/blob/main/neon-gpt/neon_gpt_ontology_generation.py)의 Step 03은 이전 명세·Few-shot 등을 사용하고 원본 description을 별도로 재첨부하지 않으므로, 첨부판의 동작을 모든 NeOnGPT 구현의 공통 규칙으로 보지는 않습니다. 이 차이는 `provenance.cq_document_input`에도 기록했습니다.

새 기본 03단계 양식은 원본 문서를 사용합니다. 기존 로그의 사용자 양식과 수동 전체 프롬프트는 덮어쓰지 않으며, 과거 문단 입력 양식도 호환을 위해 계속 동작합니다. 새 기본값으로 시작하거나 사용자 양식을 새 원문 방식에 맞춰 수정하세요.

이 정책은 전용 원문 변수와 CQ 근거를 자동으로 전달할지 정하는 것입니다. 이미 생성된 명세·모델의 인용 문구나 사용자가 붙인 원문까지 삭제하는 필터는 아닙니다. 과거 로그의 양식에 원문 변수가 남아 있어도 02·04–08단계 자동 조립에서는 빈 값으로 치환합니다. 수동 전체 메시지는 자동 조립을 우회하므로 사용자가 전송 내용을 확인해야 합니다. NeOn과 TAO의 원문 전달 방식은 변경하지 않습니다.

테스트는 출처-단계 대응, 기본값 연결, 변수 치환, JSON/CQ/Turtle 형식 요구사항, 사용자 수정 지시문의 보존과 전송 경로별 원문 제외·09단계 재연결을 확인합니다. LLM이 언제나 지시된 형식을 준수한다는 보증이나 실제 API 품질 평가가 아닙니다.
