# 저장 공간 관리

## 용량이 크게 보이는 이유

2026-09-07 측정 당시 D:는 exFAT이고 할당 단위는 128KiB였습니다.
1KiB 파일도 디스크에서는 최소 128KiB를 차지하므로 작은 파일이 많은
`node_modules`에서 파일 크기와 디스크 할당량의 차이가 크게 발생합니다.
앱 코드와 로컬 시각화 자산은 합쳐서 약 0.9MiB입니다.

| 측정값 | 정리 전 | 정리 후 |
| --- | ---: | ---: |
| 전체 파일 크기 | 422.08MiB | 약 366.5MiB |
| 파일별 디스크 할당량 추정 | 3,211.73MiB | 약 2,701MiB |
| 파일 수 | 23,192 | 약 19,430 |
| node_modules 크기 | 417.29MiB | 361.73MiB |

할당량은 각 파일의 크기를 할당 단위로 올림한 합계입니다. 디렉터리 메타데이터는
포함하지 않으므로 탐색기의 실제 값과 약간 다를 수 있습니다. 빌드·개발 캐시와
로그가 갱신되면 수치도 달라집니다. Windows 표시와 비교하기 위해 1MiB = 1,048,576바이트를 사용했습니다.

## 정리한 항목

- 사용하지 않는 `drizzle-orm`, `drizzle-kit`과 빈 DB 스키마·메모 예제.
  실제 데이터베이스나 사용자 로그를 삭제한 것이 아닙니다.
- 초기 템플릿 전용 `react-loading-skeleton`과 이미 사라진 초기 화면을 검사하던 테스트.
- npm의 `d3`와 전용 하위 의존성. OntoVis가 실제로 로드하는
  `public/ontovis/vendor/d3.min.js` 및 `D3-LICENSE`는 그대로 유지했습니다.
- 잠금 파일을 갱신하고 설치 트리에서 총 53개 패키지를 정리했습니다.
  남은 패키지 버전을 올리지는 않았습니다.

`rdflib`은 앱의 Turtle 검증에 필요하므로 유지합니다. 브라우저용 RDF 번들도
독립된 OntoVis 팝업에 필요합니다. 개발 서버, Sites/Cloudflare 빌드 도구,
TypeScript, 린트·테스트 도구도 유지합니다. 파일 개수만 줄이려고 의존성 내부의
소스·타입·라이선스를 임의로 지우지는 않습니다.

## 확인 및 재현

프로젝트 디렉터리에서 실행합니다.

```powershell
# 읽기 전용: 파일 내용이나 API 키를 읽지 않고 크기만 측정
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/measure-storage.ps1

# 현재 앱의 기능 테스트 (실제 API 호출 없음)
npm.cmd test
npm.cmd run build
```

새 작업 사본에서는 잠금 파일 기준으로 `npm.cmd ci`를 실행하면 정리된 의존성만
설치됩니다. 이 명령은 node_modules를 재설치하므로 개발 서버를 종료한 상태에서
사용하세요. 이미 설치된 현재 사본에서는 다시 설치할 필요가 없습니다.

`npm.cmd run vendor:sync`는 rdflib 브라우저 자산만 갱신하고 기존 D3를 보존합니다.
D3를 의도적으로 갱신할 때만 `npm.cmd run vendor:sync -- C:/path/to/unpacked/d3`로
`dist/d3.min.js`와 `LICENSE`가 있는 패키지 디렉터리를 지정합니다.

## 더 줄이려면

남은 용량 대부분은 개발·실행 도구입니다. 같은 기능과 개발 환경을 유지하면서
할당 낭비를 크게 줄이려면 **할당 단위가 작은 NTFS 작업 드라이브**를 사용하는
것이 효과적입니다. 드라이브를 옮기거나 포맷하는 작업은 이번 정리에 포함하지 않았습니다.

실행 중인 개발 캐시, `.env.local`, `.dev.vars`, 로컬 상태 및 사용자 작업 데이터는
삭제하지 않았습니다. 캐시만 지우면 실행 시 재생성되므로 지속적인 절감으로 보지 않습니다.
앱 화면의 입력은 메모리에 있으므로 서버를 재시작하거나 폴더를 옮길 때는 먼저 전체 로그를 저장하세요.
