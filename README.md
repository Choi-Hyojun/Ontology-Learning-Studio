# Ontology Studio

NeOn-GPT, TAO, Yonsei의 생성 과정을 하나의 화면에서 선택하고 관찰하기 위한 GUI입니다.

## 현재 구현

- NeOn-GPT 20단계 pipeline 탐색
- TAO 8개 역할/검증 단계 탐색
- Yonsei 9단계: LLM Few-shot 생성, CQ·문서·요소 연결, 문단 기반 Refine
- 이전·현재·이후 단계 보기
- 원본 NeOn-GPT 20단계 프롬프트와 단계별 변수 편집
- 전체 System/User 메시지 펼치기·직접 수정·자동 조립 복원
- 실행/일시정지 상태 및 하단 전체 진행 표시
- 외부 API 호출이 없는 자동 pipeline 시뮬레이터
- 실제 API 모드 토글, GPT/Claude 제공업체 선택, 서버 전용 키 사용
- API·실행 오류 팝업과 전체 로그 저장/복원
- 모의 `chat.completion` JSON과 `choices[0].message.content` 확인
- 각 단계의 모의 출력을 다음 단계 prompt에 자동 전달
- 전체 로그 JSON 저장·불러오기와 중간 단계 편집·재실행
- 데스크톱·태블릿·모바일 반응형 레이아웃

기본값은 시뮬레이션입니다. 이 모드에서는 약 1.1초 후 고정 예시 응답을 생성하고 해당 단계에 머무릅니다. 실제 API 모드에서는 선택한 GPT/Claude에 요청합니다. ‘실행 후 다음 단계 자동 실행’을 선택하면 연속 진행하며, 실제 API 실행 전에는 외부 전송·과금 확인을 받습니다.

## 프롬프트 편집

NeOn-GPT·Yonsei의 `domain_description`(도메인 설명)과 TAO의 `page_text`(도메인 문서 원문)에서 TXT/MD 파일을 불러올 수 있습니다. UTF-8, 최대 2MB이며 파일 선택 시 브라우저에서 읽어 기존 입력을 교체합니다. API 실행 시에는 프롬프트에 포함된 문서가 선택한 제공업체로 전송됩니다. 불러온 텍스트는 추가로 편집할 수 있습니다. 실패 시 기존 입력은 유지됩니다.

1. Prompt Context에서 persona, domain_name, domain_description, keywords 등을 편집합니다. 각 단계에서 실제 사용하는 변수만 표시되며 값은 방법론 내에서 공유됩니다. NeOn-GPT의 ontology_metrics 입력과 그 규모에 맞추라는 지시는 제거했습니다.
   같은 영역의 ‘이전 단계 출력’ 카드에는 출처 단계, 출력 본문과 글자 수가 표시됩니다. 기본값은 읽기 전용이며, 실행된 출력이 있으면 **잠금 해제** 후 수정할 수 있습니다. **적용하고 잠금**은 수정본을 다음 프롬프트에 연결하고 현재 단계 이후 결과와 해당 Yonsei Few-shot을 초기화합니다. **취소하고 잠금**이나 단계 이동은 미적용 편집을 버립니다. 편집 중에는 단계 실행과 Few-shot 생성을 잠시 막습니다. JSON·Turtle은 기존 검증을 통과해야 적용되며, 온톨로지 저장·시각화에도 수정된 Turtle을 사용합니다. 원래 요청·응답은 보존하고 수정본과 편집 이력을 v4 로그에 별도로 저장·복원합니다. 전체 프롬프트 직접 편집 모드에서는 수정본이 자동 반영되지 않습니다.
2. ‘전체 프롬프트 확인·수정’을 누르면 실제 전송할 System/User 메시지가 펼쳐집니다. 변수 값은 자동 치환됩니다.
3. 전체 메시지를 직접 수정하면 현재 단계에 한해 수동 모드가 됩니다. 수동 메시지는 변수나 이전 출력 변경에 따라 자동 갱신되지 않습니다. ‘변수로 다시 조립’을 누르면 직접 편집 내용을 버리고 최신 변수와 이전 출력으로 복원합니다.
4. ‘현재 단계 실행’ 후 ‘실행한 요청’에서 전달한 메시지를 확인합니다. ‘응답 JSON’에도 동일 요청의 스냅샷이 포함됩니다.

각 입력란과 ‘크게 보기’ 팝업의 **전체 복사** 버튼으로 전체 내용을 클립보드에 복사할 수 있습니다. Few-shot 생성 지시문·결과, 전체 프롬프트·양식 팝업에서도 사용할 수 있으며, 편집 팝업에서는 적용 전의 편집 내용이 복사됩니다. 하단 ‘현재 프롬프트’ 탭의 버튼은 현재 System/User 메시지 전체를 함께 복사합니다. LLM 출력·실행한 요청·응답 JSON 탭에서도 표시된 전체 내용을 복사할 수 있습니다.

공유 변수 변경은 해당 방법론의 실행 결과를 초기화하고, 전체 메시지 편집은 현재·이후 단계 결과만 초기화합니다. 편집값은 브라우저 메모리에만 유지되어 새로고침 시 초기화됩니다. 모의 응답은 고정 예시이며 직접 수정한 지시문의 의미를 해석하지 않습니다.

기본 예시는 첨부한 **neon example.zip / TAO example.zip의 비디오게임 온톨로지**입니다. `app/neon-prompts.json`에는 원문 20단계 프롬프트·키워드·재사용 조각·few-shot을, `app/tao-prompts.json`에는 CQ·SRD·TIP·코더·QA 원문 지시문을 반영했습니다. 두 방법론 모두 NeOn 문서에 있는 전체 Video Game 본문을 사용합니다. TAO 첨부에는 해당 원문 파일이 없어 같은 문서를 연결했다는 점을 [예시 출처와 적용 범위](docs/example-provenance.md)에 명시했습니다.

NeOn은 03단계에 명세+재사용 결과, 06–08단계에 누적 개념 모델, 09단계 이후에 최신 전체 TTL을 전달합니다. 20단계에는 03단계에서 생성한 CQ 전체도 연결됩니다. TAO는 실행된 CQ→SRD→TIP를 각 입력칸에 연결하고, QA·검토·수정 단계에 최신 TTL을 전달합니다. 아직 실행하지 않은 단계는 첨부의 기본 예시를 사용합니다. 전체 메시지 직접 편집 모드에서는 자동 연결을 중단합니다.

기존 로그를 불러와도 NeOn-GPT의 활성 입력값·템플릿·직접 편집 프롬프트에서 폐기된 metrics 항목을 제거합니다. 원본에 있던 metrics 지시 행(이미 값이 치환된 행 포함)과 해당 변수 참조 행을 정리하며, 저장된 실행 요청·출력·이력은 당시 기록으로 보존합니다. TAO에는 이 변경을 적용하지 않습니다. 새 CQ 전체 입력칸이 없는 기존 로그도 복원되며, 무관한 비디오게임 CQ를 주입하지 않습니다. 기존 로그의 문서와 템플릿은 새 예시로 강제 교체하지 않습니다.

향후 실제 생성 실행은 다음 경계로 교체할 수 있습니다.

- NeOn-GPT adapter: 각 `send_and_capture()` 결과를 공통 stage event로 변환
- TAO adapter: LangGraph의 node/tool stream을 같은 stage event로 변환
- UI transport: 긴 작업의 로그를 Server-Sent Events로 전송

## Yonsei 사용법

사용자가 제안한 초기 방법론으로, 기존 NeOn-GPT/TAO 프롬프트와 첨부 원문은 변경하지 않습니다.

1. **Yonsei**를 선택하고 01단계에서 도메인 문서와 입력값을 설정합니다.
2. 01–08단계의 **Few-shot 생성 프롬프트**를 확인합니다. 필요하면 **LLM으로 Few-shot 생성**을 눌러 예시를 만들 수 있습니다. 기본 시뮬레이션에서는 **Few-shot 모의 생성**으로 표시하며 API를 호출하지 않습니다.
3. 오른쪽 **Few-shot 생성 결과**를 검토·수정한 뒤 **현재 단계 실행**을 누릅니다. 수동 실행에서는 Few-shot을 비워 두어도 됩니다. 결과가 있으면 해당 단계의 `few_shot_01`–`few_shot_08` 변수에 자동 연결되고 단계 산출물은 아래 LLM 출력에 별도로 표시됩니다. 긴 내용은 기존 ‘크게 보기’ 팝업에서 편집합니다.
4. 03단계는 `cqs: [{id, question, evidence: [{paragraph_id, text}]}]` JSON을 생성합니다. 문단은 빈 줄 기준으로 나뉘며 `P0001`부터 ID를 부여합니다. 근거 인용이 지정 문단에 실제로 포함되는지 확인합니다.
5. 04–07단계는 `elements`와 `triples` JSON을 사용합니다. 클래스·객체/데이터 프로퍼티에는 안정적인 절대 IRI와 `cq_ids`를, triple에도 관련 `cq_ids`를 저장합니다. 05는 전체 모델, 06·07은 추가분입니다.
6. 08단계는 전체 Turtle로 직렬화하며 `https://example.org/yonsei/relatedCQ` 주석으로 CQ 연결을 보존합니다. 09 **Refine**은 문단별 원문 → 관련 CQ → 관련 클래스·프로퍼티를 ID로 묶고 최신 전체 TTL과 함께 **한 번의 LLM 호출**로 전달합니다. 관련 CQ가 없는 문단도 명시하며, 연결을 임의로 추측하지 않습니다.

**실행 후 다음 단계 자동 실행**을 켜면, 각 단계에서 유효한 Few-shot 결과가 있으면 재사용하고 없으면 먼저 생성한 뒤 해당 단계를 실행합니다. Few-shot 생성과 단계 실행은 별도 API 호출이며 사용량·이력도 따로 기록됩니다. 실제 API 자동 실행을 시작할 때는 이 추가 호출을 포함한 외부 전송·과금을 확인합니다. 수동 실행은 예시 생성을 생략할 수 있고, 단계 이동은 Few-shot이나 이전 출력 없이도 가능합니다. 단, 실제 단계 실행에 필요한 이전 산출물·CQ·온톨로지 조건은 유지됩니다.

원문/공유 입력 변경은 Yonsei 결과와 모든 생성 예시를, 앞 단계 재실행은 그 단계 이후 결과와 이후 예시를 무효화합니다. 예시·생성 프롬프트 편집은 앞 단계의 산출물을 지우지 않습니다. 전체 메시지 직접 편집 모드에서는 자동 예시 연결을 중단하며 ‘변수로 다시 조립’으로 복원할 수 있습니다.

기본 프롬프트·변수와 Few-shot 생성 지시문은 [app/yonsei-prompts.json](app/yonsei-prompts.json)에서 관리합니다. 문서·페르소나 등의 기본값은 `source_defaults`에 명시된 [app/neon-prompts.json](app/neon-prompts.json) 항목을 재사용합니다. GUI에서 수정한 생성 프롬프트/결과는 로그의 `valuesByMethod.yonsei`에 저장되며, API 요청·응답은 `few_shot_started`/`few_shot_completed` 이력에 남습니다.

Yonsei 모의 실행은 현재 문서의 첫 문단으로 연결 구조만 보여 주는 소규모 예시입니다. 도메인 의미 추출이나 실제 정제를 수행하지 않으며, Refine 모의 실행은 TTL을 그대로 유지합니다. 실제 API 결과도 근거 문자열·ID·Turtle 문법 검증이 의미적 정확성이나 OWL 논리 일관성을 보증하지 않습니다. 문단별 순차 API 호출, 추론기·CQ-SPARQL 자동 평가는 이번 초기 구현 범위에 없습니다. 긴 문서는 서버의 6MB 요청 한도 및 제공업체 문맥/출력 한도(출력 8,192 tokens)를 고려해야 합니다.

## 저장 버튼

- **전체 로그 저장 (.json)**: 현재 브라우저 세션의 모든 방법론 입력값, 첨부 문서명과 원문, 프롬프트 템플릿/직접 편집값, Yonsei Few-shot 프롬프트·결과, 시작·완료·취소·초기화 이력, 실제 전달한 요청과 응답, 현재 유효한 결과와 각 방법론의 온톨로지를 저장합니다. 변경으로 무효화된 실행이나 재실행 이전의 결과도 history에 보존합니다. 실행 중 저장은 클릭 시점까지의 기록입니다. JSON에는 입력 문서 원문도 포함됩니다.
- **온톨로지 저장 (.ttl)**: 현재 선택한 방법론의 유효한 최신 Turtle 스냅샷만 저장합니다. 로그·프롬프트는 포함하지 않습니다. NeOn-GPT·Yonsei 08 직렬화 또는 TAO 04 코더 단계 실행 후 활성화됩니다. 시뮬레이션의 NeOn 20은 첨부의 최종 merged TTL로 갱신하고, TAO 05–08은 추가 결과가 없어 04의 ver2 파일을 유지합니다. 문서나 프롬프트 변경으로 생성 결과가 무효화되면 해당 스냅샷도 제거됩니다.

NeOn-GPT/TAO 시뮬레이션은 첨부 산출물의 고정 재생입니다. NeOn 09–19 및 TAO QA·문법·추론·수정 결과는 첨부에 없으므로 **미제공**으로 표시합니다. 실행 표시가 끝나도 실제 검증 통과나 수정 완료를 뜻하지 않습니다. 입력을 바꿔도 예시 결과는 재생되며 새 온톨로지를 생성하지 않습니다. Yonsei 모의 실행의 범위는 위 사용법을 참고하세요.

실제 API 모드에서는 응답에서 Turtle을 추출하고 RDF 문법 검증 후 저장·시각화에 사용합니다. NeOn 11–20 단계의 증분 triple은 이전 스냅샷과 병합합니다. Turtle 문법 통과가 OWL 논리 일관성이나 도메인 정확성을 보장하지는 않습니다. 파일 다운로드 위치/확인 창은 브라우저 설정을 따릅니다. 새로고침 전에 필요한 로그를 저장하고 이후 불러오기로 복원하세요.

## 로그 불러오기 · 이어서 작업

1. 상단 **로그 불러오기 JSON**을 눌러 이전에 저장한 전체 로그를 선택합니다. 실행 중에는 일시정지한 뒤 사용합니다.
2. 검증 후 표시되는 저장 시각, 방법론·단계, 결과·이력·첨부 문서 수를 확인합니다. 기존 작업을 보관하려면 팝업의 **현재 로그 저장**을 먼저 누릅니다.
3. **교체하고 불러오기**를 누르면 모든 방법론의 입력값, 첨부 문서 원문, 저장된 프롬프트 템플릿·직접 편집값, 현재 출력과 요청·응답, 온톨로지 및 전체 이력을 복원합니다. 기존 프로젝트와 합치지는 않습니다.
4. 저장 시점의 단계에서 일시정지 상태로 시작합니다. 자동 진행 체크박스는 복원하지만, 사용자가 실행 버튼을 누르기 전에는 아무 단계도 실행하지 않습니다.
5. 원하는 단계로 이동해 Context나 전체 프롬프트를 수정할 수 있습니다. 공유 입력 변수 변경은 해당 방법론 전체 결과를, 전체 프롬프트 편집·재실행은 해당 단계와 이후 결과를 무효화합니다. 이전 실행 이력은 남습니다. 수동 프롬프트를 복원했다면 변수를 편집하기 전에 **변수로 다시 조립**을 눌러 자동 연결을 재개합니다.

무효화된 실행은 과거 이력으로만 보존하며 최신 결과로 되살리지 않습니다. 온톨로지 저장·시각화도 현재 유효한 실행 기록에 있는 스냅샷만 사용합니다. 다시 전체 로그를 저장하면 불러온 이력과 이후 작업을 함께 저장합니다.

UTF-8 JSON, 최대 50MB를 지원합니다. 화면의 전체 로그 저장은 Yonsei·Few-shot 및 실제 실행 메타데이터·API 요청 시도 수·오류 이력을 포함하는 v4를 사용하며 기존 v1/v2/v3 로그도 불러옵니다. 이전 로그에 없는 Yonsei 설정만 기본값으로 추가하고 기존 방법론의 작업은 유지합니다. 잘못된 파일은 교체 전에 거부합니다. 불러오기 자체는 브라우저에서 처리하며 API를 호출하지 않습니다. 실제 API 모드로 복원해도 일시정지 상태이고 실행 버튼에서 다시 확인합니다. `API 요청 시도`는 앱에서 서버로 보낸 시도 수이며, 제공업체의 실제 과금 횟수와 같지는 않습니다.

## 온톨로지 시각화

온톨로지 저장이 활성화되면 옆에 **시각화** 버튼이 나타납니다. 클릭하면
`OntoVis` 기반 팝업에서 저장 대상과 동일한 최신 Turtle을 보여 줍니다.
NeOn-GPT·Yonsei는 08 직렬화, TAO는 04 코더 단계 실행 후 사용할 수 있습니다.

- 기본 화면은 클래스 계층(TBox)이며 **Show ABox**로 인스턴스를 확인합니다. 인스턴스가 없는 스냅샷에는 빈 상태 안내가 표시됩니다.
- 휠로 확대/축소, 드래그로 이동, 노드 클릭으로 상세 정보를 확인합니다.
- 자동 실행 중 새 Turtle 스냅샷이 생성되면 열린 팝업도 갱신됩니다. 닫기 또는 Esc로 돌아옵니다.
- 시각화 자체는 외부 CDN이나 GPT API 없이 로컬에서 처리합니다. 저장과 동일한 최신 온톨로지 스냅샷을 표시합니다.

원본 `OntoVis` 폴더는 변경하지 않았습니다. 프로젝트의 `public/ontovis`에 연동용 사본이 있으며,
라이브러리 갱신 시 `npm run vendor:sync`로 RDF 배포 파일을 동기화할 수 있습니다.
D3는 이미 포함된 로컬 번들과 라이선스를 유지하며 별도 npm 의존성은 설치하지 않습니다.
D3 자체를 갱신하려면 `npm run vendor:sync -- C:/path/to/unpacked/d3`처럼 패키지 디렉터리를 지정합니다.

## 로컬 실행

### API 키 설정과 실제 실행

프로젝트 루트의 `.env.local`에 GPT용 `OPENAI_API_KEY`, Claude용 `ANTHROPIC_API_KEY`와 사용할 모델 ID(`OPENAI_MODEL`, `ANTHROPIC_MODEL`)를 입력할 수 있습니다. 필요한 제공업체 항목만 채우면 됩니다. 실제 키는 Git에서 제외되며, 공유 가능한 빈 양식은 `.env.example`입니다.

1. `.env.local`에 사용할 회사의 키와 모델 ID를 입력합니다. 값 변경 후 개발 서버를 재시작하세요. Cloudflare 로컬 실행 환경에서 비밀 환경 변수로 읽습니다. `.dev.vars`를 별도로 사용한다면 해당 파일의 우선순위에 주의하세요.
2. 웹에서 **실제 API 모드** 스위치를 켜고 **GPT / Claude**를 선택합니다. 모드·제공업체를 바꾸면 확인 후 모든 방법론의 현재 결과와 Yonsei Few-shot 결과를 초기화합니다. 문서·프롬프트와 과거 이력은 유지합니다.
3. 프롬프트를 검토한 뒤 실행 버튼을 누르고 외부 전송·과금을 확인합니다. 키 설정이나 토글 조작만으로는 호출하지 않습니다.
4. 키 누락/잘못된 키, 모델·권한 오류, 사용 한도, 네트워크·시간 초과, 잘린 응답, 잘못된 Turtle 등은 실행을 멈추고 **실행 오류 로그** 팝업으로 표시합니다. 닫은 뒤 상단 **오류 로그** 버튼으로 다시 확인할 수 있습니다.

오류를 모의 성공 응답으로 대체하거나 자동 재시도하지 않습니다. 키·인증 헤더·서버 내부 스택·원본 제공업체 오류 본문은 팝업/로그에 넣지 않습니다. 일시정지/단계 이동은 요청을 중단하고 늦게 도착한 응답을 무시하지만, 이미 제공업체에서 처리한 요청의 과금까지 취소하지는 못합니다. 기본 대기 한도는 서버 120초이며 출력 상한은 8,192 tokens입니다.

**실제 API는 localhost 전용**입니다. 현재 앱에는 사용자 인증이 없으므로 공개 도메인이나 외부 Origin에서 유료 프록시를 사용할 수 없게 차단합니다. 공개 배포에는 별도 인증·사용량 제한이 필요합니다. TAO는 텍스트 기반 단계 실행이며 원본 Python 도구 루프, 임의 코드 실행, OWL 추론기는 실행하지 않습니다. [API 연결 상세](docs/api-compatibility.md)

### 개발 서버

Node.js 22.13 이상을 설치한 뒤 (Windows PowerShell):

```powershell
npm.cmd ci
npm.cmd run dev
```

전체 기능 테스트: `npm.cmd test`. 프로덕션 빌드 검증: `npm.cmd run build`.
테스트의 GPT/Claude 요청은 모의 전송을 사용하므로 실제 API 키나 과금이 필요하지 않습니다.

용량 측정과 의존성 정리 내역은 [저장 공간 관리](docs/storage.md)를 참고하세요.
